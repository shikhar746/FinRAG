# FinRAG-Eval

A retrieval benchmark and failure analysis for question answering over long SEC
filings (10-K, 10-Q, 8-K). The system must answer analyst questions with page
citations. This project measures where it fails: parsing, retrieval, reasoning or
citation.

Evaluation comes first. A chat interface is optional and not built yet.

> **Status: MVP in progress.** Ingestion and page retrieval (BM25 vs dense) are done
> and measured on all 150 questions. Closed-book vs BM25-RAG generation (Ollama,
> `qwen2.5:7b`) is built and tested but **not yet run**. It needs a machine that can
> reach the Ollama model registry: `bash scripts/run_generation.sh`. Every number
> below is copied from `results/` by `scripts/update_readme.py`. Anything not yet
> measured is a placeholder.

## Data

[FinanceBench](https://huggingface.co/datasets/PatronusAI/financebench), open
sample: 150 questions over 84 documents (64 10-K, 8 10-Q, 6 8-K, 6 earnings releases;
`doc_period` 2015–2024), with
answers, justifications and page-level evidence.
Islam et al., *FinanceBench: A New Benchmark for Financial Question Answering*,
arXiv:2311.11944 (2023). Licence **CC BY-NC 4.0**: non-commercial use, with
attribution. The PDFs and questions are not redistributed here. Scripts download them.

## Method

```
PDF ──PyMuPDF──▶ pages.parquet (one row per page) ──▶ retriever ──▶ top-k pages ──▶ LLM ──▶ answer + [p. N] citations
                                                     (BM25 / dense)
```

- **Retrieval unit:** whole PDF pages, because the gold evidence is page-level.
- **Scopes:** `document` searches only the question's filing (the usual
  FinanceBench setting); `corpus` searches all ~12k pages of all 84 filings.
- **BM25:** `rank_bm25`, default parameters, one index per filing.
- **Dense:** `all-MiniLM-L6-v2` (sentence-transformers), run through ONNX Runtime
  with exact NumPy cosine search. The model reads only 256 tokens, so we test
  `truncate` (embed the start of the page) and `max_window` (best 256-token window).
- **Bounding baselines** (the core of the design): *closed-book* (no retrieval) is
  the lower bound and also flags memorisation/contamination. *Oracle* (the model is
  given the gold pages) is the upper bound, coming in phase 2. A real system sits
  between them, so failures can be split into retrieval vs generation failures.
- **Metrics:** Recall@k, Hit@k, MRR@100 against gold pages. Paired bootstrap 95% CIs
  for every comparison. A difference is reported as real only if its CI excludes 0.

All choices and their reasons are in [`DECISIONS.md`](DECISIONS.md).

## What the results show so far

Claims below are made only where the paired 95% CI excludes zero (tables above).
Per-question-type numbers are descriptive only (about 50 questions each, no CI).

1. **Dense beats BM25 for finding evidence pages.** Both dense variants beat BM25 on
   MRR, Recall@5 and Recall@10, in both scopes, and every one of these CIs excludes zero.
2. **BM25's failure is vocabulary mismatch.** The by-type table shows BM25 almost never
   finds the evidence for *metrics-generated* questions. These ask for a metric by its
   analyst name ("capital expenditure"), while the gold page is a financial statement
   that uses its line-item name ("Purchases of property, plant and equipment") and is
   mostly numbers. Dense embeddings bridge that gap. On *novel-generated* questions,
   which reuse the filing's own wording, the two are much closer.
3. **Reading the whole page did not help the dense model.** Best-window scoring
   (`max_window`) is not significantly different from embedding only the first 256
   tokens in document scope. In corpus scope it is slightly *worse* on MRR (CI excludes
   zero). A hypothesis, not yet tested: the start of a page carries its title
   ("Consolidated Statements of Cash Flows"), and the title is what matches the
   question.
4. **Knowing the filing matters.** Every retriever does much worse when it must search
   all 84 filings than when it searches only the right one. This is descriptive; we did
   not bootstrap the scopes against each other.
5. **Retrieval is the bottleneck to watch.** Even the best configuration misses all
   gold pages in the top 5 for a large share of questions, and RAG can only be as good
   as the pages it is given. The phase-2 oracle bound will measure this directly.

## Limitations

- **Small sample.** 150 questions in total, and only 100 in the phase-2 test set. A
  difference of a few points is usually inside the noise; see the CIs.
- **No tuning yet, so no dev/test protocol yet.** The MVP retrieval numbers use
  untuned defaults on all 150 questions. From phase 2, design choices use dev only.
- **Contamination risk.** These are public filings from 2015–2024, and any LLM may have
  seen them, or FinanceBench itself, in training. The closed-book baseline exists to
  measure this. A high closed-book score means the model's answers cannot be
  credited to retrieval.
- **Licence.** CC BY-NC 4.0 data: this project and its derived outputs are
  non-commercial.
- **PDF copies.** The PDFs came from the FinanceBench GitHub copy, not the company
  sites, which the development container could not reach
  (`data/pdfs/manifest.csv` records the source of each file).
- **Plain-text parsing.** Tables are flattened and some words are split by PDF
  kerning. A table-aware parser is a phase-2 ablation.
- **Page-level gold only.** A page counts as correct if it is a gold page, even when
  another page also contains the answer. Retrieval scores are therefore a lower bound
  on usefulness.

## Reproduce

```bash
python -m venv .venv && .venv/bin/pip install -r requirements.txt
export PYTHONPATH=.
.venv/bin/python scripts/download_data.py          # prints total size (~166 MB), asks first
.venv/bin/python scripts/download_model.py         # all-MiniLM-L6-v2 ONNX, sha256-checked
.venv/bin/python scripts/make_splits.py            # verifies the committed splits.json
.venv/bin/python scripts/ingest.py
for c in bm25_page dense_page_truncate dense_page_maxwindow; do
  .venv/bin/python scripts/run_eval.py configs/$c.yaml; done
.venv/bin/python scripts/compare.py bm25_page dense_page_truncate dense_page_maxwindow
# generation: needs Ollama installed and running (`ollama serve`)
bash scripts/run_generation.sh                     # pulls qwen2.5:7b if missing, runs both configs
# fill human_correct (1/0) in results/labels/to_label.csv, then:
.venv/bin/python scripts/score_labels.py
.venv/bin/python scripts/update_readme.py
.venv/bin/python -m pytest
```

## Layout

```
finrag/   ingest.py  retrieve.py  generate.py  evaluate.py
configs/  base.yaml + one YAML per configuration
scripts/  download_data, download_model, make_splits, ingest, run_eval, compare,
          run_generation.sh, make_label_csv, score_labels, update_readme
tests/    metrics, citation parsing, numeric matcher
results/  generated tables (committed); data/ is downloaded or derived (not committed)
```

## Roadmap

- **Phase 2:** dev/test protocol, hybrid (RRF) + cross-encoder re-ranking, oracle
  bound, LLM-judge validation (Cohen's kappa on 60 labels), failure taxonomy,
  Streamlit viewer. Add-ons: table-aware parsing; chunking ablations.
- **Phase 3:** (A) tool-using agent for numeric questions on FinQA, or (B) a new
  benchmark over Indian annual reports.
